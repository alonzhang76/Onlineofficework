三系统操作指南

采购一体化系统 · 发票与付款系统 · 收支表 —— 数据链路与角色分工

适用对象：供应商 / 采购员 / 财务 / 管理员 · AlonZhang Designed

一、三系统架构总览

三个系统通过自动桥衔接，数据沿「采购 → 报销 → 收支表」单向流动

自动桥（HTTP API 或云端 upsert）

三条数据链路

① 提交发票（采购 → 报销）：供应商在采购侧录入发票后点「提交」，通过 HTTP POST /api/invoices/external 进入报销系统「待审核」。
② 付款/审核回写（报销 → 采购）：报销系统付款与审核状态经 GET /api/payments/external + syncInvoices 自动回写采购侧发票台账；报销侧进项发票按「销售方↔供应商」模糊匹配（阈值 0.45）自动同步到采购台账。
③ 付款云推送（报销 → 收支表）：财务在报销系统点「付款」后，计算本次付款增量，弹出分类选择框；确认后生成收支记录（进项=支出 / 销项=收入），写入 transactions_<company> 并 upsert 到云端 incomeexpense__transactions_<company>，收支表 loadTransactions() 自动读取显示。
公司主体映射：龙力 → company2、普利美 → company1。三个系统均按「普利美 / 无锡龙力」两套主体分别核算，财务对账时按主体分别汇总。

二、供应商操作链路（7 步）

绿色步骤为供应商自己操作 · 灰色步骤为需方/财务动作，供应商需等待

供应商操作 需方/财务动作（供应商等待）

供应商操作要点

  • 7 步里只有 5 步是供应商动手：登录 → 登记发货 → 录入发票 → 提交 → 查看付款。
  • 第 3 步「需方确认收货」和第 6 步「财务付款」是对方动作，供应商在「需方消息」里看反馈即可。
  • 提交发票后流程自动走完，供应商无需登录报销系统或收支表。
  • 如发票被驳回，按反馈修改后可重新提交（报销系统按发票号去重 upsert）。

四、补充说明

云端数据归属

  • 采购一体化系统：独立命名空间 purchase-integrated，键前缀 pis_（合同/发货/收货/退货/发票/付款/供应商/用户/角色 等）。
  • 发票与付款系统：Flask 8686 后端 + CloudBase 共享环境 onlineofficework-d4e93l98bdf879e，发票/付款记录存 SQLite + 云端。
  • 收支表：独立命名空间 incomeexpense，键含 currentCompany/todos/reconciliation_transactions/categories 及 transactions_company1|company2。

依赖关系

  • 采购侧「提交发票」「查看付款」依赖报销系统 8686 在线（ReimPay 桥 30 秒拉取一次）。
  • 报销系统「付款云推送」依赖 CloudBase 云端可写；收支表下次加载即自动读取新付款记录。
  • 采购与收支表之间无直接依赖；采购数据须经报销付款后才进入收支表。

异常分支

  • 发票被驳回：报销系统审核反馈会回写采购侧发票台账「报销状态=已驳回」并附驳回原因；供应商修改后重新提交，按发票号 upsert 覆盖。
  • 部分发货补发：供应商在发货管理对同一合同多次登记发货，每条独立发货单；对账表「货流」列会显示「部分发货 X/Y」「已发货 X/Y」「部分收货」「已收齐」进度。
  • 销售方未匹配供应商：报销侧进项发票若销售方与采购侧供应商名称模糊匹配分 < 0.45，不会自动同步到采购台账，需人工核对。

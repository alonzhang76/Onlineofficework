# 2026-09-30 · plm-work 采购管理重构为「采购一体化」11 模块

## 背景与范围
用户要求：**以桌面端 `apps/purchase-integrated`（采购一体化，11 模块）为基准，重新设计 `mini program/plm-work` 的采购模块**；旧桌面端 `apps/purchase` 已废弃并删除。
确认范围：完整对齐 11 个模块（工作台/采购合同/发货/收货/开票/付款/对账/供应商/统计/工具箱/系统管理）。

## 关键架构决策
- **两端同源数据打通**：小程序裸键改为与桌面端一致的 `pis_*`，新增命名空间 `purchaseint`，云端 `store_key = 'purchase-integrated__' + 裸键`。
  - `utils/cloudbase.js`：`CONFIG.namespaces.purchaseint = [pis_* 共 16 键]`；`CONFIG.cloudPrefix.purchaseint = 'purchase-integrated__'`。
  - `WEB_APP_ID_MAP` 增加 `'purchase-integrated': 'purchase'`（与旧 `purchase` 归一）。
  - 桌面端 `CLOUDBASE_APP_ID='purchase-integrated'`（apps/purchase-integrated/*.html:34）。
- **付款唯一真相源改造**：桌面端付款数据来自报销系统 HTTP `/api/payments/external`（token `purchase-link-2026`），本地 `pis_payments` **全代码库无写入点**；小程序访问不到电脑 `127.0.0.1`。故新建 `Pay` 桥，从云端 `reim_invoices` 派生付款视图，字段口径对齐桌面端 `ReimPay`（`paid_amount` 封顶票面 / `payment_date` / `payment_method` / `payment_note` / `project`=合同号 / `seller_name`=供应商 / `total_amount` / `invoice_no` / `company_short` / `direction`）。能力：`paidOfInvoice/dateOfInvoice/methodOfInvoice/noteOfInvoice/auditStatusOfInvoice/paidOfContract/payRows/reconcile/syncInvoices`。
- **单号规则**：桌面端 `nextNo` 依赖 DB 计数器 `seq_<prefix>_<date>`（跨端需同步）；小程序改为**扫描当日已有单号取 max+1**，多端天然一致、不撞号。前缀 `HT-/SHP-/RCV-/RET-/SUP-/DZ-`。
- **打印替代**：桌面 `window.print` 在微信不可用 → 复用现有 Canvas→JPEG→PDF 链路（`canvas-renderer` / `pdf-builder` / `pdf-share`）。微信限制 `wx.shareFileMessage` 必须在 tap 同步栈，故 PDF 一律**两步式**（`buildFile` 生成 → 悬浮按钮 `sharePrepared`）。
- **密码兼容**：桌面端 `hashPwd` 安全上下文 `'s1:'+sha256('pis::'+pwd)`、非安全 `'f1:'` djb2 变体、种子 `'seed:admin123'`；小程序 `verifyPwd` 三形态兼容，复用 `utils/pbkdf2.js` 的 sha256。
- **Excel 替代**：桌面 xlsx → 小程序 CSV（`utils/csv.js` 新增 `exportText/exportJSON/chooseJSON`）。
